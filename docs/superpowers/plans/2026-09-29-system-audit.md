# RailScope 系统审计与修正实施计划

**目标：**以当前功能为基线，检查整仓库源码和实际数据流，修正已经复现的状态、引用、事务和性能问题。

**架构：**保留共享 `railscope.domain` 与现有 SQLite/RTree 适配器。人工覆盖采用一个权威工作区，目录交换文件仅用于种子或显式导入导出；UI、查询和派生缓存读取其已提交状态。运行引用的校验集中于共享领域入口。

**技术：**Python 3.12、PySide6、SQLite/RTree、MapLibre、FastAPI、React。

## 约束和执行

- 本任务已获授权直接执行；本会话顺序完成各阶段，不另开代理。
- 原始 PBF/GIS 只读；不更改用户当前数据，不删除历史身份和兼容文件。
- 普通几何折点不是业务决策节点；自动路径仍明确标记为参考。
- 每阶段先复现，再修正，再验证并独立提交。失败时修复本阶段后再推进。
- 全国数据量性能和显卡交互与合成数据测试分开记录，不把源码检查视为 GUI 验证。

## 重点复核

1. 缺失数据、损坏文件和失败写入保留旧状态。
2. 同名站/同名线不能使业务 ID 被替换。
3. 多选编辑和撤销是一条数据操作；历史线路成员继续可被旧通道引用。
4. 无通道车次可以暂存为 unresolved，但不能保存悬空引用或无效时刻。
5. 不同日期场景不计算彼此车次；一次调度失败不留下新占用、旧冲突混合状态。
