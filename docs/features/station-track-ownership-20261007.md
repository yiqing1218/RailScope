# 通过线路误入站内轨道修正

尧兴支线本身已经位于“轨道线 → 类别待核实 → 支线”，但三个物理区间落在货场来源轮廓内，被旧的自动空间归属规则重复收入“站内轨道”。旧规则只排除明确的 `main_track`，把用途仍为 `unknown` 的业务线路也视为可归属站线。

现在自动归属同时检查原始 `usage` 和有效轨道用途：明确的干线、支线、货运及工业业务线路，在没有站场 `service` 或人工站线分类时，不因位于设施轮廓内而变成站线。真实站场股道、段管线、渡线和明确人工归属继续保留。相同规则也用于相连的入段轨道查询，避免再次通过相连路径收入业务线路。

这是目录归属修正，不更改来源标签、几何、共享领域编号、物理拓扑或通道/车次引用，也不把未知用途强制标成已核验正线。

在本机当前全国快照中，全量检查既有自动归属并重建了站点目录，移除了 789 个不应自动归属站线的区间，包含尧兴支线的三个区间。逐项复核这些区间已经退出站线目录，尧兴支线继续保留在线路目录。审计明细位于本机 `.audit-ui/facility-classification-audit.json`，不提交大型生成目录。

归属算法版本进入站点缓存和撤销基线的签名，已有缓存会自动重建，撤销人工归属不会恢复旧的错误自动归属。专项测试覆盖四类来源用途、人工站线覆盖、真实站场保留、来源文件不变和旧缓存/基线失效。
