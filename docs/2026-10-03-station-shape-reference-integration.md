# 站场形状与参考资料整合

本次按“形状为主、拓扑辅助”的要求调整默认导出，并把网站资料接入车辆、历史与真实股道。

## 审查结果

- 此前工作树的参考资料和站场重构没有同步到实际启动目录 `D:\RailScope`。
- 车辆工作台只读取具体车组，236 条网站车型仅出现在独立参考资料弹窗。
- 车站开通日期只补入概览属性，没有写入基础设施历史。
- 等距股道布局、咽喉节点压缩和独立站台符号缩放改变了站内相对比例。
- 网站“站台编号”常指站台面，不能直接当成实体岛式站台编号或股道编号。

## 本次行为

1. `station_diagram/shape_layout.py` 使用共同的坐标变换，保留站内位置、曲线、间距和站台长宽。默认站内压缩与站台宽度倍数均为 1；站外纵向距离可单独压缩。旧默认值 4 / 1.4 自动迁移，自定义设置保留。普通几何角点只做小半径圆滑处理，实际节点与图框截断点不移动。
2. 拓扑模块仍检查真实节点连接，共享节点使用同一投影位置；不通过空间交叉建立连接，不改变物理轨道、Corridor 或 TrainRun。颜色仍来自真实线路/分场归属；不明归属继续提示。
3. 车辆页面默认显示“车型资料”，可直接搜索、阅读技术参数，用选中车型填写新车辆。具体车组与担当仍独立引用稳定车辆 ID，不生成虚构车组。共享快照与本地资料合并加载，局部导入不会遮住其他已收录车型。
4. 首次查看匹配车站的历史时，参考日期进入共享 `InfrastructureLifecycle` 的 source 层。保留多个站场/阶段的开通事件与线路范围；只到年/月的日期保留原精度，不虚构日期。人工历史覆盖优先，已有概览日期和来源冲突也保留。
5. 分场匹配同时使用网站站台面范围、已有正式股道号、真实 OSM 站台面编号及几何相邻关系。满足这些证据且无冲突时，建立实际 `StationTrack.yard_id`、参考 `platform_number` 和稳定 `Yard`；保存来源、快照、匹配证据及未核验状态。不是仅按空间位置猜颜色。
6. 缺少编号、重复编号、资料范围重叠或铁路体系冲突时不自动填写。股道编辑器的“网站分场对应”列出来源范围与具体股道候选，支持选取稳定股道 ID 并确认。人工确认随现有 override 保存，重导入后重放。
