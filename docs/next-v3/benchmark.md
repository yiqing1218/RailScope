# 实测说明

测试环境为 Windows 11 x64（26200）、Intel Core i7-13700H、16 GB RAM、NVMe 数据盘，同机有 Intel Iris Xe 与 GeForce RTX 4060 Laptop。WebView2 为 157，视口 1440×900 CSS 像素，设备像素比 1.25。动画回调采样与 GPU 绘制时间含义不同。本次没有确认激活 GPU 和屏幕刷新率，也没有采集 GPU 时间线。

全国快照 `china-osm-202609-overview` 使用原生瓦片探针。济南邻近铁路的七个动态瓦片从 Z11 至 Z21 逐级查询，单个冷请求约 0.63–93.42 ms，内存命中约 0.0001–0.0003 ms。探针只请求每级中心瓦片，这些时间不可推算复杂站场或整幅画面。原归档 Z8 读取约 0.74 ms，主要差异是顶点精度和冷瓦片上限。精度比较见[精度报告](precision-report.md)。

44 个非空全国动态中心瓦片的冷生成 P95 为 128.78 ms，其中 29 个 Z15 及以上样本的 P95 为 4.31 ms。上海源包 14 个样本的冷生成 P95 为 70.04 ms，其中 10 个 Z15 及以上样本的 P95 为 11.29 ms。北京南附近的一次 Z11 冷生成耗时 420.15 ms。抽样统计见 `data/logs/next-validation/next-v3/tile-benchmark.json`，尚无全视口冷、热瓦片 P95 对照。

新全国源包 `china-osm-202609-v3` 包体约 9.84 GB。两次启动探针完整检查文件哈希并打开数据库，分别用时 8.15 s 和 8.17 s。济南邻近铁路的 Z12 冷瓦片约 16.71 ms，Z21 和 Z22 分别约 7.90 ms 和 7.81 ms，包含同快照底图要素。北京南附近新包 Z11 单次冷生成约 647 ms，Z13–Z22 抽样约 26–47 ms。密集城市低级别冷瓦片仍有超过目标的样本。

最终原生端到端日志位于 `data/logs/next-validation/next-v3/final-native/`。上海中文站名查询单次 47.09 ms，WebView 网络拦截期间观测到 0 个外部请求。原生程序从本机安装上海源包、重放工作区并切换全国快照。强制退出并重启后，1,004 条已保存运行可读取，旧 Corridor 版本引用保留，播放时钟以暂停初始状态恢复。该验证针对程序进程退出。

## 连续地图漫游

新全国源包在阻断外部 HTTP(S) 的 WebView2 中连续测试 5 分钟，执行 186 次镜头切换。覆盖济南、虹桥、北京南、京沪高铁和高速互通等镜头及 Z4–Z22。期间观测到 0 个地图错误和 0 个外部请求。日志位于 `data/logs/next-validation/next-v3/national-native/roaming.json`。

旧全国包 `china-osm-202609-overview` 使用 0.3.0 的动态交通瓦片连续漫游 30.01 分钟，执行 1,100 次镜头切换，记录 0 个地图错误和 0 个外部请求。前两轮分别在约 14.3 和 12.1 分钟时发生调试连接中断，第三轮保留测试应用的启动会话后跑满。包含 WebView2 子进程的 51 次采样中，私有内存约 454–1,395 MiB，最早与最晚各 10 次的中位数分别为 596.5 MiB 和 680.1 MiB。本组观测有波动且后段中位数较高，仍不足以确认长时内存稳定。新全国源包的 30 分钟同条件测试尚未执行。原始记录在 `data/logs/next-validation/next-v3/roaming-supervised/`。
