# RailScope Next 0.3.0 仓库审计

本次以 `codex/railscope-next` 的 `702614f` 为基线。应用由 Tauri 2 封装，React 工作台通过 Tauri IPC 查询 Rust Core。地图从本地瓦片协议读取，目录、WGS84 原始几何和有向边存于 SQLite。Python 管道生成只读快照，独立 SQLite 保存工作区。

| 范围 | 基线观察 | 本次交付 |
| --- | --- | --- |
| 瓦片 | 全国预切包上限 Z8，MapLibre 放大既有瓦片时沿用简化折线 | Rust 从当前快照 RTree 和原始 WKB 生成高缩放 MVT，内存与磁盘缓存 |
| 底图 | 底图地理语境有限，线路颜色以专题类型为主 | 地理与交通分层，四套主题，区域包保留原始地铁颜色证据 |
| OSM | 业务实体保留来源引用和标签，成员和底层原始节点难以浏览 | 匹配原 PBF 的补全管道，原始坐标、标签、顺序、站场源几何和目录入口 |
| 拓扑 | 原子段和参考路径可查询，欠缺正式 Corridor 及运行版本 | 验证边序列和方向，保存独立的版本化通道与车次引用 |
| 运行 | Next 桌面版没有完整工作台 | 运营数据、时刻交换、Rust 时钟、运行图及三个分析层级 |
| 交付 | 支持本地构建和运行 | Windows NSIS，数据包安装校验、诊断和日志，实测见基准 |

全国既有快照的 canonical 库有 1,869,372 个交通实体。本次生成的新快照 `china-osm-202609-v3` 有 1,881,112 个交通实体、84,079,741 个原始节点、4,460,744 条原始 Way、2,090,823 条关系成员记录和 3,471,787 个地理底图要素。对应数据库与瓦片归档共 9.84 GB。上海新快照独立保存 870,072 个原始节点和 121,030 条 Way。历史帧率、内存曲线和启动时长缺少同机可比记录，基线使用可重放的归档瓦片和原快照。[精度报告](precision-report.md) [验收总表](acceptance.md)
