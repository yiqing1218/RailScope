# 铁路线命名与端点—线路通道标准

## 1. 三层引用，不复制线路

物理铁路（RL）→ 单向运行通道（COR）→ 车次。

底层轨道先在道岔、线路所、车站轨道节点、信号节点及拓扑分支处拆分。现有国铁提取器已经按这些 OSM 节点拆分。新目录进一步把同一铁路线上的连续区间组合成可复用的端点分段（RS）；几何坐标仍只有底层轨道一份。

通道每行是“起点端点、铁路线、终点端点”。相邻行共用一个端点。线路所、车站没有换线时，不必全部列出。车次引用通道编号，自己的经停、到发时刻和站台仍放在车次计划中。

例：北京南 → 京沪高铁 → 上海虹桥。反向另建上海虹桥 → 京沪高铁 → 北京南；当前不支持闭合、重复经过节点的循环通道。

这里的运行通道不是“八纵八横”规划通道分类。

## 2. 统一命名和编号

| 对象 | 编号 | 显示名称 | 可编辑内容 |
| --- | --- | --- | --- |
| 物理铁路线 | `RL-` 加 20 位稳定摘要 | 规范名称 · 完整 RL 编号 | 名称，不改编号 |
| 可复用端点分段 | `RS-` 加 20 位稳定摘要 | 所属 RL 线路、起终节点 | 原始区间引用不直接改写 |
| 省份/类型目录切片 | `RC-` 加 12 位稳定摘要 | 目录名称 · RC 编号 | 名称、分类、上下级 |
| 单向运行通道 | 用户指定唯一编号，如 `COR-JINGHU-DOWN` | 京沪下行通道 | 名称、端点—线路组合 |

RL 编号由原始线路名称（name 优先，full_name 次之）、ref、service、高速标记、在建标记计算。相同身份的轨道可以跨省归入同一物理线路。不同身份不会仅因显示名称相同而被合并。未命名轨道按 OSM Way 单独区分，例如“未命名轨道·w123”，不凭位置猜测成某条官方线路。

所有显示名称都携带编号，同名、同省、不同股道用途也可区分。改名不重新计算 RL 编号，不改写 OSM 标签，不影响已有通道或车次。RC 只是目录切片，不能把 RC 编号填到通道的 line_id 中。

入口：**编辑 → 铁路线规范命名 / 改名**；目录切片改名和分类仍在 **编辑 → 国铁轨道类型 / 通道分类整理**。

OSM 标签缺失、别名不一致可能让真实同一线路产生多个 RL 身份。不能把自动生成的身份等同于已经人工核验的全国官方铁路名录；此时可在通道中显式组合这些线路。名称编辑不会擅自合并拓扑或股道。

## 3. 通道交换格式

**文件 → 导入/导出国铁运行通道**。UTF-8 JSON，schema 为 `railscope.rail-corridors.v2`，字段严格固定：

```json
{
  "schema": "railscope.rail-corridors.v2",
  "source": "用户编制；非实际联锁进路",
  "required_capabilities": [],
  "extensions": {},
  "corridors": [
    {
      "id": "COR-JINGHU-DOWN",
      "name": "京沪下行通道",
      "sequence": [
        {"kind": "endpoint", "node_id": 9560692742},
        {"kind": "line", "line_id": "RL-f2b1dec5971012fc9df6"},
        {"kind": "endpoint", "node_id": 3687619616}
      ],
      "extensions": {"railscope.org/line-resolution": {"policy": "mainline"}}
    }
  ]
}
```

示例编号与已导入京沪高铁基础设施对应，不是已经验证的车站实际联锁端点。有全国铁路库时，G1 示例直接从该库查询真实线路与车站，重新拼接实体轨道，不读取旧车次的缓存路径。没有该库时才使用便携参考数据。其他线路应使用软件目录中的真实编号。

sequence 必须为奇数项，端点/线路严格交替。每个端点项只有 kind、node_id；每个线路项只有 kind、line_id。一个线路项只连接其左右端点。多段示例：端点 A、线路 RL-1、端点 B、线路 RL-2、端点 C。B 即换线端点，不用再重复输入 B。

导入后软件在已索引的物理铁路中解析、校验并缓存 edge_id + direction 组合；用户不用逐条输入 OSM 区间。缓存不是为车次新建 OSM 数据，同一通道可被多个车次引用。运行计划内部兼容 railscope.rail-plan.v2 的 routes；可选 sequence 保存表格，与 path 缓存保持一致。

旧 railscope.rail-corridors.v1 的明确物理 path 仍可导入。v2 表格每次从基础设施解析，不能用既有车次路径绕过解析。策略由 `extensions["railscope.org/line-resolution"].policy` 指定：

- `strict`（JSON 未指定时默认）：物理径路不唯一即拒绝，适用于精确到股道的人工编排。
- `mainline`（界面和简洁 CSV 默认）：仅在指定 RL 线路的既有非在建轨道内，按真实几何长度确定性地选择最短连接，方便“北京南—京沪高铁—上海虹桥”这样的干线拼接。不连通仍拒绝，不用直线补齐。

mainline 是几何拼接，不是已验证的上下行、信号或联锁进路；站场具体股道必须在车次层继续细化，不能据此投入真实调度。

已有通道编号不能被另一条物理路径静默覆盖。需要改变路径时，新建通道编号，再明确调整车次引用。

## 4. 获取可用编号和端点

文件菜单的通道导入/导出也支持 UTF-8 CSV，每行一个“端点—线路—端点”组合段，表头必须严格为：

```csv
corridor_id,corridor_name,segment,from_node,line_id,to_node
```

同一通道的 segment 从 1 连续递增，名称必须一致，下一行的 from_node 必须等于上一行的 to_node。支持一张表包含多个通道；整批校验后应用，失败不替换原计划。CSV 是简洁表格交换，不携带任意扩展元数据；无损交换请用 JSON。

**文件 → 导出铁路命名与端点分段** 导出 `railscope.rail-lines.v1` 目录，包含：

- lines：RL 编号、规范显示名称、原名、区间数量；原始 edge_ids 在 sections 的 path 中完整保留。
- endpoints：可引用的真实轨道端点 node_id 及已知名称；离开轨道的站房 POI 不是可直接引用的节点。
- sections：RS 编号、所属 line_id、from_node、to_node、轨道用途 track_type、分类依据 type_evidence、在建状态 construction、长度 length_m、可复用 path。显示名称为“线路及 RL 编号 · 用途 · 起点 → 终点 · RS 编号”。原始坐标仍留在基础设施中。每根底层 edge 恰好属于一个分段；道岔、跨线连接、已知端点和用途变化处断开。尚未切分的线内节点不能直接作为站场替换端点，未来新增切分和迁移约束已写入 AGENTS.md。

AI 编写通道时只使用该目录中的 line_id 和 node_id。先导入或提取基础设施，再导入通道，最后导入引用通道编号的车次 JSON/CSV。目录导出不是基础设施备份，跨电脑仍需对应基础设施；便携 G1 可用内置参考数据。

## 5. 站台和真实性边界

`platform_id`（旧整数 Way）或 `platform_ref`（`way/编号`、`relation/编号`）属于车次 stops，不属于通道表格。不同车次可以共用通道、停靠不同站台。真实轮廓与地图层共用同一 source ID；未知编号拒绝。新 relation 引用和嵌套站场路径请用 JSON，旧 CSV 无法无损保存时明确拒绝导出。

可选 `trains[].station_paths` 描述仅此车次的站场进出区间：每项包含整数 `from_node`、`to_node`、实际 `path`、`extensions`，可选 `sequence`。两端必须为共享通道中已切分且按行车顺序排列的端点，区间不能重叠；替换径路必须在真实轨道中连续，并回到指定出口端点。地图和动画使用替换后的实体轨道，但共享通道原定义不变。同一停站的 `track_change` 预留信息也可按车次独立编辑；文字说明本身不改变径路。

旧通道的 track_changes 兼容读取，不自动把它推断成实际站台分配。新版换线位置由相邻线路之间的端点表达；尚未实施真实道岔状态、方向许可、信号联锁或调度安全验证。

规范名是可追溯的本地显示名，不是对 OSM 原名或官方铁路命名的破坏性覆盖。

## 6. 编辑和性能

左侧「运行」→「国铁」→「共享通道」新建或编辑通道表格，双击目录项也可编辑。新建自动提供唯一通道编号及端点名称，均可修改。先搜索选择线路，再搜索该线路的端点；也可输入准确的节点编号。每个搜索框最多展示 100 个候选项。组合段可上移、下移，应用前校验相邻端点是否一致。每个通道有独立显示开关，可同时显示多个共享通道；显示的是通道底层轨道，不是某个车次的站场绕行。使用通道面板的「保存通道与国铁车次」持久保存。导入后同样需要保存。

全国线路目录使用本地 SQLite 索引，首次准备有进度和取消按钮，后续直接复用。规范命名窗口每页最多 100 条，支持搜索、翻页和跨页保留未保存修改。命名修改保存后立即作用于通道选择和线路目录。索引可从基础设施重建；名称配置属于用户数据，应和计划一起备份。

RL 编号对同一份源身份稳定；如果未来 OSM 的原始身份字段发生变化，需要核对映射，不能保证跨任意数据版本自动匹配。

国铁目录项和分组支持右键「重命名」「移动到文件夹」「归档」。移动可选择现有文件夹或输入 `我的目录 / 虹桥站 / 站场股道` 这样的多级路径；目录组织独立于原始轨道类型和省份。归档后关闭对应地图显示，移入「已归档」，右键可恢复原目录，恢复后显示保持关闭。重命名只改变本地显示名，RC/RL 编号、OSM 原名、几何和车次引用保持不变。目录设置保存在用户分类配置中，不移动或删除实际 GIS 文件。
