# 铁路线命名与端点—线路通道标准

## 1. 三层引用，不复制线路

物理铁路（RL）→ 单向运行通道（COR）→ 车次。

底层轨道在道岔、线路所、车站轨道节点、线路归属变化点、拓扑岔接点和线路端点处拆分，普通曲线折点不拆分。导入器会收录 OSM 明示的 `station`、`halt`、`stop`、`junction`、`signal_box`、`switch` 等点，并从轨道连接度补出未命名拓扑岔接点。新目录再把同一铁路线上的连续区间组合成可复用的端点分段（RS）；几何坐标仍只有底层轨道一份。

通道每行是“起点端点、铁路线、终点端点”。相邻行共用一个端点。线路所、车站没有换线时，不必全部列出。车次引用通道编号，自己的经停、到发时刻和站台仍放在车次计划中。

例：北京南 → 京沪高铁 → 上海虹桥。反向另建上海虹桥 → 京沪高铁 → 北京南；当前不支持闭合、重复经过节点的循环通道。

这里的运行通道不是“八纵八横”规划通道分类。

## 2. 统一命名和编号

| 对象 | 编号 | 显示名称 | 可编辑内容 |
| --- | --- | --- | --- |
| 轨道控制点 | 持久化 `NN-` 编号 | 原名或“未命名线路所” | 别名，不改编号或来源 |
| 物理铁路线 | 持久化 `IL-` 编号；旧便携数据兼容 `RL-` | 简洁、唯一的业务线路名称 | 名称和目录，不改编号 |
| 可复用端点分段 | `RS-` 加 20 位稳定摘要 | 所属 RL 线路、起终节点 | 原始区间引用不直接改写 |
| 单向运行通道 | 用户指定唯一编号，如 `COR-JINGHU-DOWN` | 京沪下行通道 | 名称、端点—线路组合 |

全国铁路重新导入时，身份注册表负责保持 `NN`、`NE`、`IL` 编号；OSM Node/Way ID 只保留为来源别名，不进入新的长期通道引用。旧便携数据仍可读，导出表格时会尽可能迁移成稳定控制点编号。未命名线路所统一显示为“未命名线路所 · 线路所 · NN-…”，不伪造地名；有原名时显示为“原名 · 线路所 · NN-…”。

按端点形成的内部可复用区间统一命名为：`线路规范名｜起点—终点｜轨道类型｜RS-…`。RS 用于拓扑校验、引用迁移和路径展开，不要求用户在目录或通道中逐段选择。整条物理线路仍保留自己的 RL 编号和可读名称。

对象标题只显示简洁名称，稳定编号在概览属性中单独展示。同名对象仍由编号唯一识别。改名不重新计算 IL 编号，不改写 OSM 标签，不影响已有通道或车次。RC 只是目录切片，不能把 RC 编号填到通道的 line_id 中。

入口：**编辑 → 铁路线规范命名 / 改名**；目录切片改名和分类仍在 **编辑 → 国铁轨道类型 / 通道分类整理**。

OSM 标签缺失、别名不一致可能让真实同一线路产生多个 RL 身份。不能把自动生成的身份等同于已经人工核验的全国官方铁路名录；此时可在通道中显式组合这些线路。名称编辑不会擅自合并拓扑或股道。

## 3. 通道交换格式

**文件 → 导入/导出国铁运行通道**。UTF-8 JSON，schema 为 `railscope.rail-corridors.v2`，字段严格固定：

```json
{
  "schema": "railscope.rail-corridors.v2",
  "source": "用户编制；非实际联锁进路",
  "required_capabilities": [],
  "extensions": {},
  "corridors": [
    {
      "id": "COR-JINGHU-DOWN",
      "name": "京沪下行通道",
      "sequence": [
        {"kind": "endpoint", "node_id": 9560692742},
        {"kind": "line", "line_id": "RL-f2b1dec5971012fc9df6"},
        {"kind": "endpoint", "node_id": 3687619616}
      ],
      "extensions": {"railscope.org/line-resolution": {"policy": "strict"}}
    }
  ]
}
```

示例编号与已导入京沪高铁基础设施对应，不是已经验证的车站实际联锁端点。有全国铁路库时，G1 示例直接从该库查询真实线路与车站，重新拼接实体轨道，不读取旧车次的缓存路径。没有该库时才使用便携参考数据。其他线路应使用软件目录中的真实编号。

sequence 必须为奇数项，端点/线路严格交替。每个端点项只有 kind、node_id；每个线路项包含 kind、line_id，可选 section_id 指定真实 RS 区间。一个线路项只连接其左右端点。多段示例：端点 A、线路 RL-1、端点 B、线路 RL-2、端点 C。B 即换线端点，不用再重复输入 B。

导入后软件在已索引的物理铁路中解析、校验并缓存 edge_id + direction 组合；用户不用逐条输入 OSM 区间。缓存不是为车次新建 OSM 数据，同一通道可被多个车次引用。运行计划内部兼容 railscope.rail-plan.v2 的 routes；可选 sequence 保存表格，与 path 缓存保持一致。

旧 railscope.rail-corridors.v1 的明确物理 path 仍可导入。v2 表格在当前基础设施中解析或校验已保存的选择。策略由 `extensions["railscope.org/line-resolution"].policy` 指定：

- `auto`（桌面新建通道默认）：先检查整条端点链的连通性，再优先选择靠近车站的可达接轨点，在线路内用长度最短的运营路径作为参考；方向限制、真实断轨和非运营状态仍须校验。人工指定的端点和 RS 区间优先。
- `strict`（JSON 未指定时默认）：物理径路不唯一即拒绝，适用于精确到股道的人工编排。
- `mainline`（旧文件兼容）：现在与 strict 一样要求唯一，不再以几何最短路消解多股道或分支。旧文件遇到歧义会要求补充中间控制端点。

唯一连通也只证明当前基础设施快照中的物理可连通性，不等于已验证的上下行、信号或联锁进路；站场具体股道必须在车次层继续细化，不能据此投入真实调度。

自动模式在同一扩展内保存 `selection`（用户选择、解析端点、区间引用）、算法版本、数据快照与自动参考状态；没有经核验的置信度时 `confidence` 为 null。重新打开或导入时校验并保留已选路径，缺少区间会报错。手工修改端点、线路或区间后重新解析，并通过整批计划校验后应用；不会为每个车次复制基础设施几何。

### 站前、站后自动换线

自动模式不能直接沿所选线路拼接时，会对中间换线站读取局部连接图。换线站允许使用前后两条线路各自的接轨点，无须强制同一个节点同时属于两条线路。逐行联合寻路允许在换线站周边经过真实股道、渡线、联络线，每行至少经过一段所选线路；按完整路径长度选择，并剔除回头重复经过节点的组合。人工明确指定的 RS 区间不会被替换；固定接轨约束无法满足时仍报错。

只在换线站周边依次查询 3/8/20 km，找到可用连接即停止扩大范围。SQLite RTree 限定节点范围，`edges(a)`、`edges(b)` 索引获取局部实际轨道；不生成几何连接，也不把第三条全国干线全部载入内存。14 版索引可从 13 版直接补建这两个索引。

解析结果使用原基础设施线路和区间编号展开成实际 sequence/path，连接轨也写入成员快照。`selection.requested_sequence` 保留用户原来的“仙宁线—南京南—沪蓉线”表格；`selection.resolved_sequence` 和 `selection.path` 保留展开结果。再次编辑默认显示原表格，也可展开已保存的实际路径后手工修改。JSON 和 CSV 均携带选择记录。

## 4. 获取可用编号和端点

文件菜单的通道导入/导出也支持 UTF-8 CSV，每行一个“端点—线路—端点”组合段，表头必须严格为：

```csv
corridor_id,corridor_name,segment,from_node,line_id,section_id,to_node,extensions
```

同一通道的 segment 从 1 连续递增，名称必须一致，下一行的 from_node 必须等于上一行的 to_node。`extensions` 只在每个通道首行填写 JSON 对象，用于保留自动参考路径、拼接策略及线路归属快照。旧版不含 extensions 或 section_id 的表头仍可导入，未指定策略时按 strict 校验。桌面编辑器默认自动选择，可通过中间端点或 `section_id` 手工调整。支持一张表包含多个通道；整批校验后应用，失败不替换原计划。

**文件 → 导出全国铁路图（端点—线路—端点）** 导出 `railscope.rail-graph.v1`，包含：

- lines：IL 编号、规范显示名称、原名、轨道类型和底层 edge 数量；原始 edge_ids 在 sections 的 path 中完整保留。
- station_entities：唯一车站实体、可落到真实轨道的 anchor_node_ids、相接线路和关联核验状态。
- endpoints：真实轨道控制点、坐标和相接线路；离开轨道的站房 POI 不会冒充物理控制点。
- sections：RS 编号、所属 line_id、from_node、to_node、轨道用途 track_type、分类依据 type_evidence、在建状态 construction、长度 length_m、可复用 path。显示名称为“线路规范名｜起点—终点｜轨道类型｜RS 编号”。原始坐标仍留在基础设施中。每根底层 edge 恰好属于一个分段；道岔、跨线连接、已知端点和用途变化处断开。

AI 编写通道时只使用该目录中的 line_id 和 node_id。先导入或提取基础设施，再导入通道，最后导入引用通道编号的车次 JSON/CSV。目录导出不是基础设施备份，跨电脑仍需对应基础设施；便携 G1 可用内置参考数据。

## 5. 站台和真实性边界

`platform_id`（旧整数 Way）或 `platform_ref`（`way/编号`、`relation/编号`）属于车次 stops，不属于通道表格。不同车次可以共用通道、停靠不同站台。真实轮廓与地图层共用同一 source ID；未知编号拒绝。新 relation 引用和嵌套站场路径请用 JSON，旧 CSV 无法无损保存时明确拒绝导出。

可选 `trains[].station_paths` 描述仅此车次的站场进出区间：每项包含整数 `from_node`、`to_node`、实际 `path`、`extensions`，可选 `sequence`。两端必须为共享通道中已切分且按行车顺序排列的端点，区间不能重叠；替换径路必须在真实轨道中连续，并回到指定出口端点。地图和动画使用替换后的实体轨道，但共享通道原定义不变。同一停站的 `track_change` 预留信息也可按车次独立编辑；文字说明本身不改变径路。

旧通道的 track_changes 兼容读取，不自动把它推断成实际站台分配。新版换线位置由相邻线路之间的端点表达；尚未实施真实道岔状态、方向许可、信号联锁或调度安全验证。

规范名是可追溯的本地显示名，不是对 OSM 原名或官方铁路命名的破坏性覆盖。

## 6. 编辑和性能

左侧「运行」→「国铁」→「共享通道」新建或编辑通道表格，双击目录项也可编辑。先选车站/线路所 A，软件只推荐与 A 相接的业务线路；选择线路后，只推荐该线路上可到达的下一车站/线路所 B；再从 B 继续选择相接线路。同名、同位置的站点、站房和轨道锚点合并为一个车站实体，候选文字同时列出接轨业务线路。普通道岔、站场股道、渡线、车辆段线和折返线不作为普通端点或业务线路候选；它们仍保留在底层物理图和对象详情中。默认自动选择一条可走通的参考路径；勾选「手工调整」可显示实际道岔和轨道节点，也可用「选择本行物理区间」指定 RS 区间。每个搜索框最多展示 100 个候选项。解析结果必须从首端点开始并在末端点结束，不允许越过端点。地图显示自动展开后的完整 NetworkEdge 有序序列。

车站目录右键或地图对象详情可以编辑车站/线路所的“接轨线路”。首次打开显示系统识别结果；人工保存后，工作区覆盖列表成为该端点的权威候选。每条新增关联必须在车站 2500 米内找到所选业务线路的真实图节点，并保存线路稳定编号、锚点编号、距离和用户核验状态；无法找到真实节点时拒绝保存。该覆盖只改变车站实体与既有轨道节点的关联，不创建虚构轨道，也不改写原始 OSM。

基础设施“全量”指当前导入快照中所有明确标注对象和所有可由轨道连接关系确定的决策点。OSM 本身缺失的官方线路所名称无法凭空恢复，软件保留稳定未命名控制点，允许在 override/workspace 层补名，并明确保留来源和核验状态。

全国线路目录使用本地 SQLite 索引，首次准备有进度和取消按钮，后续直接复用。目录默认完整显示当前快照中已有名称的业务线路，未命名 OSM 轨道通过主搜索框输入“未命名轨道”后单独整理，站场分组不再混入线路目录。规范命名窗口每页最多 100 条，支持搜索、翻页和跨页保留未保存修改。右侧对象详情或分类整理窗口保存的名称、轨道类型和目录位置会写入同一工作区覆盖层，并立即作用于线路目录、通道候选和图导出；原始 OSM 不改写。索引可从基础设施重建；名称配置属于用户数据，应和计划一起备份。

IL/NN/NE 编号由身份注册表跨快照迁移；无法安全匹配的拆分、合并或并行轨道变化会产生 conflict，不能静默改绑旧通道。

国铁目录项和分组支持右键「重命名」「移动到文件夹」「归档」。线路目录展示业务线路分类，车站目录按省、市组织车站实体及线路所/道岔；不把全国数十万 RS 当作用户目录叶子。具体 RS 保留在对象属性、图导出和解析缓存中。自定义文件夹只改变工作区展示。重命名不改变 RS/RL/NN/NE 编号、OSM 原名、几何和车次引用。
