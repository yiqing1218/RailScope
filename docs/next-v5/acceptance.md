# RailScope Next 0.5.0 地图与运行验收

从仓库运行 `Start-RailScope-Next.cmd`，或使用构建生成的 Windows x64 安装包。图层偏好、原始 OSM 对象、运行数据和用户覆盖仍在相应快照与工作区中保存。

## 地图与运行界面

| 功能 | 操作 | 数据依据 |
| --- | --- | --- |
| 底图降噪 | 地图 → 图层 → 底图与地理参考 | 中倍率默认保留城市、区县、水系及道路骨架。乡镇与村庄、普通道路名、普通兴趣点名可独立启用。 |
| 铁路、城轨和公路标注 | 地图 → 图层 → 对应交通分组 | 精细瓦片以业务关系成员选取沿线标签段，按线路身份在各瓦片稀疏取样。符号、线、站名、线名和专业叠加分别控制。 |
| 查看相关线路 | 选择车站 → 右侧相关线路 | OSM 线路直属成员、存有明确关系的 stop_area 成员链分别保留证据。物理接轨依据轨道锚点查询。可打开线路详情、定位高亮并返回车站。 |
| 编排共享通道 | 运行 → 共享通道 → 打开通道编排 | 底部保留端点、接轨线路、下一可达端点三列。通道图层显示当前选中的完整有向物理径路。 |
| 上海地铁交路图 | 运行 → 车次与时刻 → 选上海地铁车次 | 站序或里程纵轴、多车计划、双向筛选、时窗、点击车站定位及点击运行图跳转时钟。现有通道和车次模型继续提供径路与时刻。 |

Rust 在既有 RTree 和 MVT 生成入口增加标签投影，无需重建全国数据包。标签使用当前交通实体的稳定渲染 ID，工作区改名覆盖显示文字。城市与次要地名分层。方向、线名、操作层与仿真保持独立。全国高倍率仍按原始几何生成瓦片。

## 旧通道实际迁移

本机找到旧版两份通道导出和运行计划的 22 个不同通道编号。原 JSON 和旧 SQLite 以只读方式读取。迁移查找相同 OSM Way 与原始节点，复核区段方向及连续性。旧路径不可重放时，可在保留原端点和明确线路成员证据的条件下尝试重新编排。无唯一可用物理路径的记录保留审校理由。

全国 v3 的本机 RailScope Next 工作区已保存 **7 条旧通道**，例如合肥南至福州、南京至上海、许昌东至北京丰台。另保存 **1 条京沪高铁新版参考通道**，用同站的不同物理锚点和当前 OSM 线路 356778 的 670 段有向物理区段。原京沪旧档出现与现有单向标记相反的区段，因此仍保留为待审记录。

共 **15 条旧记录待审**。迁移报告包括旧编号、当前 UUID、区段数及冲突原因。重复导入已验证保留现有 UUID 和版本。写入前使用 SQLite 备份 API 保存本机工作区。相关文件留在项目的 `data/processed/railscope-next/migrations/`，未纳入提交。

重复生成迁移候选可使用 `railscope-next/pipelines/migrate_corridors.py`，按顺序输入新版 canonical.sqlite、旧版有数据的 rail_lines.sqlite、输出 JSON 和一份或多份旧通道／运行计划 JSON。输出可在「数据 → 导入旧版计划」校验。

## 验收范围

- 0.4.0 和 0.5.0 使用同一份全国 v3 数据包，在武汉、上海、北京、济南的相同位置和相同窗口截图。Windows 生产构建、Rust 核心 10 项、前端符号 2 项、Python 数据管线 4 项、旧后端 72 项通过。
- 武汉 `114.3247°E, 30.5658°N, Z9.3` 对应中心精细瓦片包含 23 个铁路业务线名、13 个城轨线名候选、12 个城市或区县地名，站名、可见范围和碰撞由 MapLibre 控制。Z22 仍按源几何请求。
- 独立验证全国快照的铁路线名／线几何、城轨站名／站符号以及模式切换。济南 Z12.9、Z21、Z22 生成源精度瓦片，实测离线网络外部请求为零。跨线通道、运行图拖动、车组冲突、工作区撤销重做和 GTFS 往返均通过。
- 上海 1 号线公开资料重建样例有 28 站、38 段物理轨道。另用两端折返测试生成 3 趟计划，同图验证顺向和反向。样例时刻用于离线运行功能验证。

### 同视角性能抽样

窗口为 1440×900 CSS 像素，DPR 1.25。加载用时从设置相机到测试判定瓦片队列稳定，并包含 450 ms 稳定等待。帧率是随后 1 秒的 WebView 帧采样。下面的数据来自单次顺序运行，缓存冷热和同场景 CPU、内存未统一测量。

| 视野 | 0.4.0 加载 / FPS | 0.5.0 加载 / FPS |
| --- | ---: | ---: |
| 武汉 Z9.3 | 0.50 s / 135 | 3.91 s / 135 |
| 上海 Z11.7 | 2.81 s / 135 | 0.48 s / 129 |
| 北京 Z10.4 | 0.48 s / 114 | 0.47 s / 135 |
| 济南 Z11.2 | 0.49 s / 134 | 0.48 s / 134 |

武汉中心 Z9 冷生成瓦片抽样为 2.50 s、1.71 MB。武汉首载仍明显慢于同次旧版样本。各图截图、独立瓦片抽样及 JSON 在本机 `artifacts/next-v5/`。

现有概览瓦片缺少完整业务标注，部分 Z9 以下地图仍依赖旧归档。多关系站点的自动合并仅能使用已收录的关系证据。缺少官方联锁、官方等级、未收录站线、当前列车位置和既有通道的旧证据时保留参考或待审状态。全国既有快照未重新抽取。
