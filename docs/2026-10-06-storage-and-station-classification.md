# 磁盘清理与车站目录分类

## 磁盘占用

清理前文件体积约 **124.8 GiB**，清理后约 **13.8 GiB**。两轮清理期间磁盘可用空间增加约 **86.5 GiB**。临时坐标索引含稀疏文件，因此文件体积与实际磁盘占用不同。

原始全国 OSM PBF 约 1.49 GiB。项目还保存导入后的轨道几何、线路索引、目录缓存、地铁/道路数据库和人工工作区，正常运行所需文件不会只有 PBF 那么大。

占用异常主要来自以下可重建缓存（表中为文件体积）：

| 内容 | 体积 |
| --- | ---: |
| 导入后遗留的 `.idx` 坐标索引 | 39.7 GiB |
| 性能测试复制的国铁数据库 | 42.7 GiB |
| 根目录历史 pytest / audit 临时目录 | 22.3 GiB |
| 日志目录中的测试副本和重复 Python 环境 | 6.3 GiB |

保留原始 PBF、当前正式数据集、旧数据集、人工工作区、运行记录、报告、图片、导入日志及备份。根目录 22 个历史临时目录及 `backend/.audit-cache` 无法读取，均保留，未强行修改权限；体积统计不包括这些目录内部不可读取的内容。

本轮两个预览临时目录共约 0.4 MB，直接删除被自动审批策略拒绝，只返回“被策略阻止”，未提供具体原因，已保留。其余已识别且可读取的清理候选均已处理。

以后可以先检查，再清理：

```powershell
cd D:\RailScope
.\scripts\clean_workspace_cache.ps1
.\scripts\clean_workspace_cache.ps1 -Apply
```

脚本校验所有删除路径位于项目内，拒绝清理含链接的目录；检测到导入、测试或性能测量进程时拒绝执行删除。清理范围仅包括明确的测试目录、重复验证环境和导入临时坐标索引。

自动导入的索引改用父进程管理的独立缓存。即使项目是英文路径，临时索引也放入缓存；子进程退出释放 Windows 映射后清理。性能测试和目录审计也改由父进程删除工作目录，避免 Qt 留着 SQLite 连接时删除失败；失败会明确报错。

## 目录规则

车站按两个独立字段分类，用语参照[国家铁路局公开的《铁路技术管理规程（2006）》第184条](https://source.nra.gov.cn/xxgk/gkml/ztjg/gfzd/bmgz/202206/t20220624_327439.shtml)：

- 技术作业性质：中间站、区段站、编组站。
- 业务性质：客运站、货运站、客货运站。
- 车辆段、动车段/所、检修设施、机务设施、货场、各类车场及线路所等放入“其他”，下保留原设施类型。

目录结构为 `省 / 市 / 技术作业性质 / 业务性质 / 原有自定义子目录 / 车站`；其他设施为 `省 / 市 / 其他 / 原设施类型 / 原有子目录 / 设施`。没有证据的分类显示“技术作业待核实”或“业务性质待核实”，不默认归为中间站。

调整的是目录分组，不删除、合并或重建基础设施对象。车站、设施及其轨道的编号和归属保持原样。原有地理目录及自定义目录保留；编辑器分别提供两个性质字段，修改写入现有人工工作区，可撤销和重做。

OSM 的 `yard` 有时表示整个编组站或货运站。只有具备对应位置的明确车站分类资料时，才把这样的整体站场按车站分组；单个车场、车辆段和检修设施仍在“其他”。

## 查证结果

全部 **12,738** 个目录对象都有审计记录：**10,349** 个车站对象、**2,389** 个其他设施。检索了 10,321 个具名候选对象的公开条目，没有遗留网络失败；195 个车站对象没有可用站名，其余设施按来源名称和标签整理。

- [逐项清单](../data/catalog/station_classification_audit.csv)：名称、两种性质、查证结果与资料来源，可用 Excel 打开。
- [统计结果](../data/catalog/station_classification_audit.summary.json)。
- [分类参考及字段来源](../data/catalog/station_classification_reference.json)：资料链接、页面版本、查询时间及核验状态。

| 字段 | 有明确分类参考或人工选择 | 待核实 |
| --- | ---: | ---: |
| 技术作业性质 | 446 | 9,903 |
| 业务性质 | 2,126 | 8,223 |

193 个车站的两项性质均有参考，2,186 个只明确一项，7,970 个两项均缺少依据。因此 **10,156 个车站至少一项仍待核实，尚未达到全部查明的要求**。补齐需要更完整的官方车站表、现行《站细》或明确列出本站两种性质的资料；不能把缺失字段默认为中间站或客运站。

资料只提取信息框和首节中明确的分类描述，过滤历史用途、邻站、同名不同位置、地铁等不匹配结果。公开页面资料标记为 `source_unverified`，没有冒充已核验的现行铁路业务数据。每项分类保存 source、snapshot/version、查询时间、verification_status/confidence。人工已有明确选择优先于公开参考资料。

另外核对了[铁科院的编组站系统资料](https://www.rails.cn/ths/html/proservice/product/bianzuzhan.html)和[中国通号的车站系统报道](https://www.crsc.cn/news/tsi_4691_9732_28697.html)，补入 17 个明确列名车站的技术作业分类。保存页面校验和与查询时间；未把旧报道当作当前营业办理情况的证明。

不能从车站等级、是否停旅客列车、站场大小或地图股道数量推定技术作业性质；单个客运/货运正向标签也不能证明另一种业务不存在。正文提到附近编组站或历史站型，不作为本站当前分类依据。

## 验证

完整桌面测试集 **435 项通过**。包含分类独立性、同名/位置不符资料拒绝、历史站型拒绝、目录移动不重复分类层级、撤销/重做、轨道归属和局部更新检查。真实子进程测试确认索引由父进程缓存收容，并在子进程退出后清除。

后续目录相关检查 75 项通过，最终分类检查 12 项通过。

使用离屏 Qt 实际生成并检查了分类目录预览。未重跑全国 OSM 导入；本次只清理导入临时文件并验证缓存生命周期。

实际目录重建后，12,738 个车站/设施目录对象、74,488 个关联设施、32,319 个站内轨道对象的编号和数量均与原目录一致。逐项比较原有子目录归属，确认只增加分类层级；原始 PBF、正式几何/拓扑数据库与人工工作区的大小和修改时间保持原样，SQLite 检查通过。

小型目录审计和实际全国数据副本的 26 类编辑计时均成功，原数据未改变、无异常，也未访问 PBF。父进程在测试进程结束后自动删除了副本工作目录。

正在运行的 RailScope 进程使用旧代码。保存当前工作并重新打开 RailScope 后，新目录规则生效。
