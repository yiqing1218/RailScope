# 国铁目录与 G1 参考运行图

## 当前可用功能

- 启动只有底图，地铁、国铁、车站、站台、在建工程、车辆图层全部关闭。
- 全国国铁下载/提取在 **数据源菜单**，不会占据图层侧栏。
- 已有国铁数据在后台升级省级目录，无需重下 PBF。每个轨道段按沿线半长度点落入的省级多边形归类，同名跨省线路分省列出。
- 省界参考数据为 geoBoundaries 2019 年省级多边形，不是权威测绘资料；省界附近/覆盖范围外保持待核对。编辑菜单可以人工调整省份、通道、分段，不修改 OSM 原始属性。
- **运行 → 国铁 · 车次 / 跨线运行图 → 打开国铁运行表 / 运行图**：内置 G1 七站、按车次选择独立时刻表 / 运行图，开始/暂停/关闭仿真、导入导出。
- G1 小型参考资产随源码提供，不依赖先下载约 1.5 GB 全国 PBF。不会自动启动 G1 或覆盖已保存的用户计划。

## 独立运行工作区与 G1 入口

运行菜单分成地铁与国铁两组。地铁管理交路/车辆循环，国铁管理车次/跨线径路；计划文件、时钟、撤销历史和车辆源独立。切换运行类型会暂停两个仿真并隐藏非当前类型的车辆，避免叠加误读。Ctrl+S 保存当前类型计划。

不存在加载 G1 按钮。无已保存国铁计划时自动准备内置 G1，启动仍只有底图，不显示或运行列车；打开国铁工作台直接看七站时刻表。已保存用户计划优先，不自动覆盖。参考径路开关与车辆图层独立控制。

工作台“新增车次”引用现有车次的共享径路和时刻模板，可平移首班时间，再逐站编辑；车次编号必须唯一，一车次不能增挂多个动画列车。运行菜单提供 CSV 批量导入与表格导出。任何一行错误整批拒绝，原计划保留；CSV 不重新下载、寻路或生成 OSM。首次注册新径路须导入严格 JSON，明确已有物理区间，不能凭几个站名猜线路。

时刻表可为每个车次 stop 填写站台、到发线和已登记的车站进路；它们不写入长距离共享通道。旧版共享变道字段仍可读取并迁移，但不再作为新数据的职责边界。未知留空；这些信息不驱动实际道岔、股道或联锁。

左侧“通道”替代“定位”，与“图层 / 运行”平行，仍共用主地图。文件菜单提供独立通道导入 / 导出。每条 Corridor 保存从起点边界到终点边界的完整连续 edge 序列，中间车站隐含在物理路径中；直达、大站停和站站停车次可以引用同一条 Corridor，只在各自 stops 中不同。反向或跨线运行需另建完整通道。运行通道与八纵八横规划图层分类是两个不同概念。

车辆可见性在运行侧栏按国铁车次字头 / 单车次、地铁线路 / 单车次统一控制。隐藏只影响动画显示，不删除车次或改变时刻。全部轨道仍共用既有基础设施。图层目录仅由外侧滚动，模块随展开增长。**地图 → 铁路类型颜色 / 线宽** 可保存各轨道类型样式，在建轨道保留虚线。

工作台居中、最大宽度 1120 逻辑像素。按钮区固定紧凑高度，时刻表/运行图优先使用剩余空间；国铁默认给表格更多高度，仍可拖动地图下方分隔线调整。收起后可以从对应侧栏重新打开。

## 铁路分类规则

默认目录为 **轨道类型 → 高速规划通道 → 省份 → 分段/线路**；仅高速主线有规划通道层。也可切换 **省份 → 轨道类型 → 线路**。类型包含高速、普速、货运、联络线、支线、渡线、站场股道、动车走行/检修线、折返线与未确认类型。同名同省轨道按不同用途拆开，不再把站场和主线混合。

自动分类是应用内参考判定，不改写原始 OSM 标签：

- `service=crossover` 作为渡线；`service=spur` 作为支线/岔道；`service=yard/siding` 作为站场股道。站场是否高速/货运需另有明确标签或名称依据，不按靠近高铁站就猜测。
- 明确的联络/疏解、折返/立折、动车走行/段场名称优先于高速主线判定。
- `usage=industrial/freight` 或 `passenger=no` 判为货运；`highspeed=yes` 或明确高速铁路名称判为高速；`highspeed=no` 或 main/branch 且标注速度≤160 判为普速。缺少证据归入未确认类型。
- “匝道”按用户目录习惯显示为联络线，不表示铁路中另有公路式匝道；道岔本体仍在国铁点要素中，渡线是连接轨道，二者不混淆。

OSM 依据：[service](https://wiki.openstreetmap.org/wiki/Key:service)、[highspeed](https://wiki.openstreetmap.org/wiki/Key:highspeed)、[usage](https://wiki.openstreetmap.org/wiki/Key:usage)。

通道名称依据国家发展改革委 [八纵八横说明](https://www.ndrc.gov.cn/fggz/fzzlgh/gjfzgh/202112/t20211224_1309311.html) 和 [中长期铁路网规划](https://www.ndrc.gov.cn/fggz/zcssfz/zcgh/201607/W020190910670620449319.pdf)。根据规划中的走向，对已明确命名的区段建立参考映射，不用模糊名称/地理位置猜通道。城际/区域连接线、共线部分、未命名线段未确认时仍为“高速通道待核对”，不强行塞进十六条主通道。

**编辑 → 国铁轨道类型 / 通道分类整理** 可修改轨道类型、省份、通道、分段；通道选择提供十六条规划通道，也允许输入自定义分类。已有数据后台自动升级，无须重下 PBF。

## 当前领域模型：固定基础设施 + 完整通道 + 车次停站计划

v2 把完整连续物理路径从每个车次抽成共享 `routes`/Corridor，车次只引用 `route_id` 与自己的经停/通过、站台、到发线和车站进路；导出和保存使用 v2，仍兼容 v1。旧的逐车局部路径覆盖会迁移为另一条完整 Corridor。内存中相同径路共用几何对象，地图参考径路去重显示，不为每个车次生成 GIS 文件。

已实现 `railscope.rail-corridors.v2` 端点—线路—端点导入，编译时复用基础设施的真实区间，不要求每个车次携带 OSM 几何。表格编排、RL/RS 稳定命名与两种解析策略详见 RAIL_LINE_NAMING_AND_CORRIDORS.md。以下业务控制点及通过时刻体系仍需进一步核验：

基础设施表维护稳定的 `line_id`、`section_id`、`from_control_point_id`、`to_control_point_id`、方向、所属线路、真实几何和底层 OSM 区间映射。控制点包括车站、线路所、接轨点等。基础设施版本必须固定，避免数据更新后同一编号含义漂移。

车次区间表每行记录：

`train_id, sequence, section_id, entry_control_point_id, exit_control_point_id, entry_time, exit_time`

另有车次经停表：

`train_id, sequence, station_id, arrival_time, departure_time, platform_id(optional)`

车次按顺序引用已整理的区间，跨线只在已确认连接的控制点发生。列车跨线不是乘客换乘。无需给每辆车重新搜索全国 OSM，但仍需要连续几何供动画显示。

仅有“线路名 + 两端点 + 时间”，在区间路径唯一时足够；遇到支线、联络线、多股道、环线等歧义，必须额外指定 `section_id` 或候选径路，不能悄悄猜测。无法确认的组合应报错并让用户选择，而不是以最近距离连接断点。

到发时间不等于中间每个线路所的真实通过时刻。未提供时可以生成明确标为“估算”的仿真，通过时间、速度曲线、越行与跨线接续等后续能力通过命名空间扩展添加。
