# 中国动车组参考属性

桌面端“数据 → 从中国动车组补全参考属性…”读取网站的线路、车站与具体车型参数。“数据 → 线路、站场与车型参考资料…”可搜索全部已取得资料。

参考文件位于 `data/user_settings/china_emu/reference.json`，属于独立工作区参考层，不修改 OSM、GIS geometry、物理轨道、通道、进路或车次。参考数据不随代码提交。源页面缓存复用七天；重新导入保留暂时读取失败的旧页面，并记录失败列表。取消时保留已有参考文件和已取得的缓存。

属性优先级为人工编辑、已有源属性、网站参考。相同名称的线路采用精确匹配；车站还须有地区或所在线路证据。同名来源有歧义时保持未匹配。改名、重新导入或线路归属发生变化后重新匹配，无法安全匹配的记录不自动迁移。

整条线路只显示所有区段一致的参数。不同区段的速度、线间距、到发线长度、列控系统等在对象详情中按原有范围分别列出。计价里程不替代底图长度，也不从某个区段推广到整条线路。轨道结构（有砟/无砟）不改写线路的业务分类。

车站的各组站场规模、场名、适用线路和站台编号分别保存；多组站场不会合并成未经证实的总规模。网站的站场图只视作来源生成的参考，不能生成真实站台边界、RailScope Platform ID、StationRoute 或调度进路。车型参数按具体来源版本保存，可查询编组、速度、尺寸、功率、轴重、列控等；没有明确车型对应关系的具体车辆、车次不自动绑定。

每份资料保存来源 URL、获取时间、页面 SHA-256 版本、未核验状态和 confidence（未评估时为 null）。与人工/OSM 值不同的参数在对象详情中显示资料差异。

命令行导入：

```powershell
$env:PYTHONUTF8 = '1'
python -m desktop.import_china_emu --rail-directory '你的当前底图目录'
```

`--rail-directory` 只读已有的 `rail.sqlite` 和 `rail_catalog.sqlite`，仅抓取当地已有站名；不指定时读取网站目录内的所有车站。导入完成后 `coverage.json` 给出线路对象匹配和车站名称候选统计，车站候选仍需界面中的地区/线路匹配，不代表已经关联。
