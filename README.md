# RailScope · 轨道交通工作台

RailScope 是一个以 **Windows 原生桌面端**为主要入口的地图与铁路运行编辑工具。它使用本地 OpenStreetMap 数据展示全国地铁、国铁与高速公路，支持目录整理、对象详情、共享运行通道、车次时刻表和参考运行仿真。

地图几何、基础设施和运行计划分别管理。软件用于数据整理、可视化与运行组织研究；OSM 连通关系和动画结果不代表已核验的实际调度、信号或联锁进路。

## 快速开始

### Windows 用户

1. 下载当前 `feature/desktop-workbench` 分支的 ZIP，完整解压到可写文件夹。
2. 安装 **64 位 Python 3.12 或兼容的新版本**，确保 `python` 或 `py` 命令可用。
3. 双击根目录的 **`Start-RailScope.cmd`**。
4. 首次启动会建立项目内 `.venv`、安装桌面依赖，并下载校验地图组件，需要联网。
5. 软件默认仅显示底图。打开左侧图层开关，或通过 **数据** 菜单下载所需基础设施。

桌面端使用 PySide6 / Qt WebEngine / MapLibre，无需启动 FastAPI，也无需安装 Node.js、Docker 或 PostGIS。GitHub 当前提供源码，尚不是免安装 EXE。

不要在 ZIP 内运行，也不要复制其他电脑的 `.venv`。中文路径和含空格路径可使用。启动日志保存在 `data/logs/startup.log`。

启动检查：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File desktop/Run-RailScope.ps1 -CheckOnly
```

已有 Python 环境也可以手工启动：

```powershell
python -m pip install -r desktop/requirements.txt
python desktop/launcher.py
```

## 数据下载与导入

全国数据不随 GitHub 源码分发。仓库保留小型示例；没有全国数据时仍可启动，并使用内置国铁参考示例。

| 需要的数据 | 软件入口 |
| --- | --- |
| 全国地铁线路、站点、真实站区与在建工程 | 数据 → 下载或更新全国地铁数据… |
| 全国国铁轨道、车站、道岔、站台与站区 | 数据 → 下载或更新全国铁路数据… |
| 全国高速公路 | 数据 → 从全国 OSM 建立高速公路目录… |
| 省、市、县行政边界 | 数据 → 从全国 OSM 建立省市县行政边界… |
| 目录分类与人工整理结果 | 数据 → 对应线路／车站数据 → 导入目录分类… |
| 国铁通道、车次和地铁运行计划 | 数据 → 通道数据／车次数据／地铁运行数据 |

- 地铁和国铁流程复用本机全国 OSM PBF；公路导入也使用该文件。原始下载体积与快照有关，建议为原始文件和派生索引预留至少 10 GB 空间。
- 下载支持暂停、续传和版本校验。导入完成后才切换活动数据集；导入期间请等待任务完成再退出。
- 已有完整 PBF 时可复用，不必反复下载。更新网络快照时再启用重新下载选项。
- 读取地图时使用 SQLite 空间索引。首次导入或索引版本升级会花费额外时间。
- 基础设施在本地不等于底图已离线下载；在线底图、卫星图与初次依赖安装仍需要网络。
- 数据来自 OSM，设施覆盖和属性质量取决于快照。缺少真实站区、站台轮廓时，不用圆圈或推测多边形冒充真实边界。

下载／导入日志：`data/logs/`。活动数据集由 `data/processed/` 中的清单指定；请优先通过软件完成导入和切换。

## 地图与目录操作

### 选择、定位与显示

- RailScope 标题旁的四个工具依次为：抓手与单击选择、框选道岔、框选线路、框选站点。
- 目录支持多选和批量操作。地图选中对象后可查看详情、定位目录；目录双击可定位地图。
- 地铁、公路和国铁的各层目录可勾选；国铁站场股道、站台线和已关联道岔也有独立开关。选择目录行不会替换已有显示选择，双击线路会定位完整范围。
- 国铁车站与地铁站点分别控制，开启某城市的国铁站点不会开启该城市的地铁站点。
- 地铁站点可以单独显示，不需要先开启地铁线路；取消一个站点或城市的勾选不会关闭其他城市。
- 对象详情可编辑显示名、目录位置与支持的业务属性。人工修改保存在工作区覆盖层，原始 OSM 标签保留。
- 道岔可重命名；选中的多个真实道岔可用于建立线路所，归属和接轨关系仍需核验。

### 合并与拆分线路目录

在地图框选或目录多选国铁线路段后，右键选择 **将所选铁路段组合为一条线路…**，填写组合名称。不同文件夹中的目录段可以放入同一组合。

组合后可右键 **拆分所选组合线路**，恢复组合前的目录位置。组合拥有稳定的工作区编号，**目录组合与通道查询使用同一套线路成员归属**：组合后可在通道中选择新线路，拆分后新通道按独立线路选择。原始轨道及编号保留；组合不会补画断轨，也不会将一个物理 NetworkEdge 任意切成两段。

自动归到一起的同名线路目录也能拆分。拆分状态保存在工作区中，刷新目录后不会立即重新合并。

组合、拆分和撤销都保存历史组合的成员定义。既有通道继续引用原路径，通道导出同时携带线路成员快照；重新导入后若缺少成员，会报告 `conflict`，不会悄悄改走另一条路。

### 省、市、县行政区域底图

展开 **图层 → 底图**，可选择标准地图、卫星影像，以及 **行政区域 · 省级／市级／县级** 三种行政底图。

- 行政底图使用淡色分区、加粗边界和地名标注；省级为蓝紫边界、市级为青绿边界、县级为棕橙边界，样式与标准道路底图区分。
- 首次选择行政底图时，如本机已有全国 PBF，会在后台建立 `data/processed/admin/admin.sqlite`；也可从数据菜单手动建立或更新。
- 之后按地图视窗读取 SQLite + RTree；启动配置不包含全国行政区多边形。缩小时使用简化显示几何，放大后读取更细边界。
- 中国 OSM 的省、地级、县级分别对应 `admin_level=4/5/6`；特别行政区按来源标记归入省级浏览，直辖市在市级视图也保留轮廓。[OSM 中国边界约定](https://wiki.openstreetmap.org/wiki/China/Boundaries)
- 这是 OSM 参考边界，不是官方审定地图。快照中缺失或无法组装的边界不会用推测多边形填补；行政底图轮廓可离线使用，地名字体首次加载仍可能需要网络。

### 控制最远显示距离与加载量

**显示 → 各类元素最远显示级别…** 可分别设置地铁线路、地铁站、地铁站区、在建工程、国铁线路、车站与线路所、道岔、站台、站区和高速公路。

- 数值越小，地图缩得越远时仍允许显示。
- `0` 表示不设缩放门槛。
- 实际显示还取决于图层开关、目录选择和视窗加载预算。

**显示 → 地图元素加载上限…** 可调整国铁视窗的要素数、字节数、顶点数和单个要素大小，提供默认、高内存、自定义和无限制设置。默认每次请求为 6,000 个要素、8 MiB 数据、100,000 个顶点，单个要素不超过 1 MiB。无限制可能增加当前视窗的内存与地图处理时间。

### 高速公路目录

```text
公路
├─ 国家高速
│  ├─ 国家干线
│  └─ 区域线路
├─ 省级高速
│  └─ 各省目录
└─ 待核对高速
```

各层目录与线路均有显示开关。国家干线按放射线、纵线和横线编号归组；地区环线、绕城、联络和并行线路放入区域线路。该分组用于浏览，不改写 OSM 原编号或官方属性；无法识别的编号保留待核对。[编号依据：交通运输部说明](https://xxgk.mot.gov.cn/jigou/glj/202006/t20200623_3312189.html)、[国家公路网规划](https://www.gov.cn/zhengce/zhengceku/2022-07/12/5700633/files/1ca992f13a81434b89e222eb000acada.pdf)。

## 通道、车次与运行仿真

运行数据遵循三层结构：

```text
共享物理 NetworkEdge → 单向完整 Corridor → TrainRun 与 stops
```

1. 在通道编排中按“端点—线路—端点—线路—端点”定义完整连续路径。
2. 存在多条合法路径时继续补充中间端点，不静默采用几何最短路作为正式进路。
3. 多个车次可以引用同一完整 Corridor，分别设置停车、通过、到发时刻、站台和到发线。
4. 反向和跨线运行使用对应的完整 Corridor，不为每个车次复制基础设施几何。

### 线路能看见，通道却选不到终点时

- 程序会自动识别因 `highspeed` 等分类标记不同而分开的同一线路。只有名称、线路编号等归属一致，且共享真实轨道节点，才会用于同一线路的通道查询。原分类与源编号保留；同名、不接轨的线路保持独立。
- 新建通道默认使用 **自动选择可走通的参考路径**。选好起点、线路、终点即可应用；车站有多股轨道时，先检查整条通道是否连通，再优先使用靠近所选车站的接轨点，并在所选线路上选择较短的可运行路径。断轨、非运营区间和禁止的方向仍会报错。
- 例如“上海站—沪宁城际线—仙林站”，站名和线路已经确定，但站内可能存在多个物理接轨点。默认模式会完成这个选择，不再要求逐个选择道岔。需要逐一消除歧义时，可改用 **严格唯一径路**。
- **自动站内换线**：例如第一行填“仙林—仙宁线—南京南”，第二行填“南京南—沪蓉线—全椒”。两条正线没有共用接轨点时，程序会查找南京南附近的真实股道、渡线和联络线，自动补入完整通道，支持站前或站后换线。每一行仍须经过你指定的线路，不会按地图距离跨接断轨。
- 换线查询先查站点周边 3 km，未找到时扩到 8 km、20 km；只加载这些区域的索引轨道及所选线路，不加载全国几何。超出范围或缺少连续运营连接时会提示手工核对。旧版线路索引只补建轨道端点索引，不重新解析全国 OSM 数据。
- 自动选择的具体端点和路径会随通道保存，重新编辑、保存及 JSON/CSV 导入导出保留原选择。CSV 的 `extensions` 列在每个通道首行携带路径选择和线路归属快照，旧表头仍可导入。修改端点、线路或物理区间后重新解析；已保存区间缺失时报告错误。结果标记为自动参考路径，记录算法版本和数据快照，不冒充已核验的调度进路。
- 旧版车站详情保存的“手工接轨线路”会继续保留；其中自动产生的最近轨道点作为候选提示，避免锁住不可达的另一股道。明确选择的物理端点和区间仍严格按人工选择校验。
- 在通道编排勾选 **手工调整**，可按编号搜索实际道岔或轨道节点，增加中间端点指定所走分支。也可用 **选择本行物理区间…** 指定已有 RS 区间及方向；手工选择优先于自动选择，保存和再次编辑会保留。若线路归属本身有误，可先在目录或地图中拆分、重新组合，再编排通道。
- 已保存通道仍以原来的车站和业务线路显示。需要检查自动补入的连接轨时，点击 **展开已保存的实际轨道路径，手工调整连接轨…**；手工模式也能选择未命名股道和渡线。
- 非运营轨道和方向不允许的轨道不会出现在可达终点查询中。真实断轨仍需核对基础设施数据，目录组合不生成虚构连接。

例如本地全国快照中的仙宁线曾被分为 44 个普速分类区间和 12 个高速分类区间；只查其中一组会漏掉南京南。统一查询后，“仙林站—仙宁线—南京南站”可解析为 26 个连续物理区间。此结果属于 OSM 几何校验，仍不代表实际联锁进路。

可重复运行索引诊断（仅加载选中线路的图结构）：

```powershell
python -m desktop.audit_corridor --start 仙林 --line 仙宁线 --end 南京南 --report data/processed/corridor-audit.json
```

诊断包含全国自动归组结果、所选通道的接轨端点、区间数、成员快照及未解决原因。加 `--policy auto` 检查默认自动参考路径，加 `--workspace data/user_settings/rail_catalog.json` 检查本地人工覆盖；索引版本过旧时，打开通道编排自动更新，或用 `--rebuild-index` 重建。更新只发生在派生 SQLite 索引，首次会显示准备进度。

**运行 → 国铁运行** 提供车次工作台、CSV 批量导入、计划保存、导入导出与仿真控制。内置 G1 是参考示例，不是实时列车或官方调度数据。

**运行 → 地铁运行** 提供交路、车辆循环、投放、时刻表和运行图编辑。当前地铁运行编辑开放上海；其他城市可浏览基础设施。地铁与国铁的计划、时钟和显示控制分别管理。

目录调整与运行编辑保留各自支持的撤销／重做；计划修改后请保存。单纯的目录组合不替代运行通道的连续性与方向校验。

## 数据存储与性能实现

| 部分 | 当前实现 |
| --- | --- |
| 全国地铁几何 | SQLite + RTree；地图通过 `/api/metro` 按视窗和当前选择查询 |
| 全国国铁几何 | SQLite + RTree；保留国铁视窗查询和可配置预算 |
| 高速公路 | SQLite 空间索引、按视窗查询、目录选择过滤 |
| 行政区域底图 | 省／市／县分级索引，SQLite + RTree，按视窗与缩放读取边界 |
| 地铁线路、地铁站、高速目录 | `QTreeView + QAbstractItemModel`，SQLite 分页，按展开需要加载，复选状态绘制 |
| 国铁目录元数据 | SQLite 读取和有界记录缓存；目录开关已去掉逐行真实 QWidget |
| 地图传输 | 防抖、请求去重与重复源更新抑制；配置中不再嵌入全国地铁站点／站区几何 |
| 人工编辑 | 独立工作区覆盖文件；基础设施源数据与运行引用保留 |
| 通道线路归属 | SQLite 索引加少量归组映射；只读取所选线路的轨道图，端点与路径校验放在后台执行 |

**尚未完成的架构部分：**国铁线路和车站目录仍有 `QTreeWidget` 实现与节点数量限制，尚未全部迁移到 SQLite 分页 Model/View；部分国铁编辑仍会重建目录。现阶段不能声称所有全国目录的内存都已与总数据量无关。大规模静态几何的 MVT／矢量瓦片传输也尚未实现。

国铁目录开关现在增量同步已显示行，不因勾选而重建目录；文件夹的完整成员由磁盘索引提供，包含超过当前列表上限的成员。大规模地图选择使用 HTTP 请求正文传递，避免全国站点 ID 超过 URL 长度上限后地图为空。

## 仓库结构

| 路径 | 用途 |
| --- | --- |
| `Start-RailScope.cmd` | Windows 桌面启动入口 |
| `desktop/` | Qt 工作台、嵌入地图、SQLite 索引、目录与运行界面 |
| `backend/` | 共享 `railscope.domain`、服务、导入器、FastAPI、数据库迁移与测试 |
| `frontend/` | React / Vite Web 开发界面；不属于桌面启动必需项 |
| `data/demo/`、`data/catalog/` | 小型示例与版本管理的目录配置 |
| `data/raw/`、`data/processed/` | 本地原始输入与可再生 GIS / SQLite 输出 |
| `data/user_settings/`、`data/logs/` | 本地覆盖、运行设置与日志 |
| `docs/` | 领域约定、数据交换、开发与功能说明 |
| `docs/history/` | 早期阶段计划和报告，仅用于追溯 |
| `docker-compose.yml`、`.env.example`、`Makefile` | 可选后端服务与开发命令 |
| `AGENTS.md` | 项目修改、验证和数据约束 |

原始 PBF、大型派生数据、`.venv`、地图组件缓存、用户设置、日志和测试临时目录不提交。更新代码前建议备份 `data/user_settings/`；不要用原始 OSM 文件承载人工改名或运行计划。

## 开发与验证

### 桌面与后端测试

在仓库根目录执行：

```powershell
python -m pip install -e "./backend[dev]" -r desktop/requirements.txt pytest-qt
$env:PYTHONPATH = "$PWD\desktop;$PWD\backend;$PWD"
$env:QT_QPA_PLATFORM = "offscreen"
python -m pytest backend/tests desktop/tests -q --basetemp .pytest-work/full
```

地图脚本语法检查（需要 Node.js）：

```powershell
node --check desktop/assets/map.js
```

这些测试覆盖逻辑与离屏 Qt 行为；完整的底图联网、显卡渲染和长时间交互还需在实际桌面环境验证。

### Web / 后端开发

Web 工具链使用 Node.js 22.12+ 的兼容版本。桌面用户可跳过本节。

```powershell
python -m pip install -e "./backend[dev]"
Set-Location backend
python -m uvicorn railscope.main:app --reload
```

另开终端：

```powershell
Set-Location frontend
npm ci
npm run dev
```

示例 API 不依赖外部数据库。需要 PostGIS 开发服务时，在根目录从 `.env.example` 建立本地 `.env`，再运行 `docker compose up -d db`。环境文件不提交。

```powershell
Set-Location frontend
npm test -- --run
npm run build
```

## 常见问题

**启动失败：**查看 `data/logs/startup.log`，运行 `-CheckOnly`。如果 `.venv` 来自其他机器，重命名备份后重新运行启动脚本。

**地图只有底图：**先确认数据已导入，再打开对应图层与目录开关。检查当前缩放级别是否低于该类元素的显示门槛。

**局部要素不完整：**检查是否达到视窗预算，并尝试放大或缩小目录选择范围；同时核对 OSM 快照是否包含该设施。

**导入失败但 PBF 已下载：**保留完整下载文件，关闭重新下载选项后重试。查看具体导入阶段日志，失败不会主动切换当前活动数据集。

**应用通道较慢：**通道需要解析稳定端点和连续拓扑。索引、目录和地图加载已做部分优化，但全国国铁目录的完整懒加载改造仍在进行。
